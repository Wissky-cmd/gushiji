# 注释检查技能

本项目的"注释质检"：检查代码注释的数量、准确性、通俗度，输出中文报告。

## 检查标准（用户 2026-09-17 拍板）

1. **注释数量**：每一个函数、每一条重要的核心代码，都应该有详细注释；
   整体比例目标：10 行代码中约 3 行注释、7 行正文（约 30% 注释覆盖率）。
2. **注释匹配**：注释说的必须和代码实际干的是一回事；禁止"注释说往东、代码往西"的误导注释。
3. **小白可读**：注释写出来要让不懂编程的人也能看懂；避免技术黑话，必须用术语时要顺带解释
   （例如写到"IPC"时要说"界面和后台之间传话的通道"）。

## 执行流程

1. **定范围**：用户指定文件就查指定文件；没指定就查 `src/` 下全部代码（`.ts` 与 `.vue` 文件，
   node_modules 与打包产物除外）。
2. **逐文件三查**：按上面三条标准检查，记录每一处问题（哪个文件、哪一行、属于哪类问题、
   为什么不行、建议改成什么样）。
3. **出报告**：按下方模板输出中文报告。
4. **修复需批准**：默认只出报告、不动代码；用户明确说"改"之后才动手改注释，改完复检并汇报。

## 统计方法

- 注释行 = 以 `//` 开头的行、`/* … */` 块注释内的行、HTML 注释 `<!-- -->` 行、JSDoc `/** … */` 行。
- 注释覆盖率 = 注释行数 ÷ 文件总行数，四舍五入到百分位。
- 每个导出函数/方法必须有注释：说明它"干什么、吃进什么、吐出什么"。

## 报告模板（中文、通俗，沿用用户拍板的报告样式）

```
## 注释检查报告

📊 检查 X 个文件 · 平均注释覆盖率 XX% · 发现 Y 处问题

各文件注释覆盖率（条形图）：
文件名A     ███████ 70%
文件名B     ███ 30%
…

| 文件 | 注释覆盖率 | 缺少注释 | 注释不符 | 不够通俗 | 结果 |
|---|---|---|---|---|---|
| … | … | N 处 | N 处 | N 处 | ✅/⚠️ |

🔍 comments-check 执行过程
1. （实际干的步骤，一步一行）

**问题明细**（若有）：每条列出 文件:行号 + 什么问题 + 建议怎么改。

**结论**：一句话总结，如"注释总体良好，X 处需要补充/修正"。
```

## 注意事项

- 检查时只看注释，不改代码逻辑；发现注释与代码不匹配时，先判断是注释错了还是代码错了，
  在报告里说明，由用户决定改哪边。
- 覆盖率是参考指标，不是死线：短小的纯函数（如 formatMoney）注释少是正常的，不必凑数；
  核心业务函数（如记账、统计）注释必须详细。
